갸웃 서비스 기획서
========================================

서비스명: 갸웃
한 줄 소개: 수업을 함께 듣고, 학생과 교수 사이에서 대신 손을 들어 주는 AI
이름의 의미: 이해가 되지 않아 고개를 갸웃하는 순간을 놓치지 않는다
해커톤 주제: 2. 더 나은 캠퍼스를 위한 AI (AI for Smarter Campus)
문서 버전: v1.0

1. 문제 정의
----------------------------------------

수업 중 학생과 교수 사이의 실시간 쌍방향 소통이 원활하지 않다.

[1.1 학생 측면]

- 이해하지 못한 내용이 있어도 다음 이유로 질문하지 않는다.
1. 수업 흐름을 끊을 것에 대한 부담
2. 자신만 모르는 것일 수 있다는 불안
3. 무엇을 모르는지 스스로 정리하기 어려움
- 한 번 놓친 내용이 이후 학습 내용의 이해를 연쇄적으로 어렵게 한다.
- 교수의 설명 자체를 이해하지 못하는 경우가 있다.

[1.2 교수 측면]

- 학생에게 질문을 해도 응답이 없어 학생들의 이해도를 판단할 수 없다.
- 학생의 참여와 응답이 저조하여 수업 진행 의욕이 저하된다.

2. 해결 방안
----------------------------------------

[2.1 개요]

실시간 강의 음성 인식 기반의 익명 질문·응답 서비스를 제공한다.

- 학생 → 교수: 학생이 익명으로 남긴 모호한 질문을 AI가 해당 시점의 강의 내용과 연결하여 구체적인 질문으로 다듬고, 같은 내용의 질문을 묶어 교수에게 전달한다.
- 교수 → 학생: 교수가 수업 중 말로 던진 질문을 AI가 감지하여 학생 화면으로 전송하고, 학생들의 익명 응답을 집계·분석하여 교수에게 제공한다.

[2.2 기존 방법의 한계와 차별점]

- 직접 질문
    한계: 수업 흐름 단절, 타인의 시선 등 심리적 부담
    갸웃의 해결 방식: 익명 질문, 교수가 원하는 시점에만 질문 전달
- 익명 채팅
    한계: 학생이 무엇을 모르는지 정리하지 못하는 문제(1.1의 3번)를 해결하지 못함
    갸웃의 해결 방식: AI가 강의 내용과 연결하여 질문을 구체화
- 질문 게시판
    한계: 수업 종료 후 이용하므로 실시간 소통이 아님
    갸웃의 해결 방식: 수업 중 실시간 전달
- AI 챗봇
    한계: 학생 혼자 해결하는 방식으로, 교수는 학생이 어디서 막혔는지 알 수 없음
    갸웃의 해결 방식: 질문이 교수에게 모이는 양방향 구조
- Slido 등 익명 Q&A 도구
    한계: 수업 내용을 알지 못하여 "방금 그거"와 같은 질문을 해석할 수 없음
    갸웃의 해결 방식: 실시간 강의 음성 인식으로 질문 시점의 강의 내용과 매칭
- AskNow (해외 연구, 2025)
    한계: 실시간 음성 인식 기반 질문 해석은 존재하나, ① 학생의 확인 절차가 없고 ② 의미 기반으로만 질문을 묶으며 ③ 교수 → 학생 방향의 소통 기능이 없고 ④ 국내 수업 환경에 적용된 서비스가 아님
    갸웃의 해결 방식: ① 다듬은 질문을 학생이 승인 ② 강의 시점 기준으로 질문을 묶음 ③ 교수 질문 감지 및 익명 응답 분석 ④ 한국어 강의 지원

3. AI의 역할
----------------------------------------

- 질문-수업 내용 실시간 매칭
    내용: 질문이 접수된 시점을 기준으로 최근 강의 음성 인식 결과에서 질문이 가리키는 부분을 찾는다
- 질문 다듬기
    내용: 학생이 입력한 내용을 구체적이고 정중한 질문 문장으로 바꾼다. 문체가 통일되어 작성자 추정이 어려워진다
- 거르기
    내용: 수업과 무관하거나 부적절한 입력을 판별하여 제외한다
- 교수 질문 감지
    내용: 교수의 발화 중 학생의 응답을 요구하는 질문을 찾아내고, 학생 화면에 표시할 문항으로 정리한다. 교수가 스스로 답하는 수사적 질문은 제외한다
- 응답 분석
    내용: 학생 응답에서 공통적으로 나타나는 오해를 찾아 요약한다

4. 서비스 구성 및 기능
----------------------------------------

[4.1 교수 화면 (노트북·프로젝터)]

- P-1
    기능: 수업방 생성
    설명: 수업 제목을 입력하면 수업방이 생성되고, 접속용 방 코드와 QR 코드가 표시된다
- P-2
    기능: 교안 PDF 업로드
    설명: 교안 PDF를 업로드한다. 필수 여부는 7장에서 결정한다
- P-3
    기능: 강의 음성 인식
    설명: 교수의 강의 음성을 실시간으로 인식하여 서버에 저장한다. 인식 결과는 화면에 표시하지 않는다
- P-4
    기능: 질문 목록
    설명: 학생 질문을 강의 시점별로 묶어 인원수 순으로 표시한다 (예: "12명 · 행렬식을 0으로 놓는 이유")
- P-5
    기능: 질문 읽어 주기
    설명: 교수가 [질문 읽어 주기] 버튼을 눌렀을 때에만, 가장 많은 학생이 남긴 질문을 음성으로 읽어 준다
- P-6
    기능: 교수 질문 감지 알림
    설명: 교수의 질문이 감지되면 "학생들에게 보낼까요?" 알림과 함께 [보내기]·[무시] 버튼을 표시한다
- P-7
    기능: 교수 질문 직접 입력
    설명: 감지와 별도로 교수가 질문을 직접 입력하여 보낼 수 있다
- P-8
    기능: 응답 결과
    설명: 응답 마감 후 답변 분포와 흔한 오해, 다시 설명할 내용을 표시한다. 교수가 요청하면 요약을 음성으로 읽어 준다

[4.2 학생 화면 (모바일)]

- S-1
    기능: 접속
    설명: QR 코드 또는 방 코드로 로그인 없이 익명으로 접속한다
- S-2
    기능: 질문 입력
    설명: 입력창에 질문을 입력한다. "ㅁㄹ", "?" 등 짧은 입력도 허용한다
- S-3
    기능: 질문 승인
    설명: AI가 다듬은 질문을 보여 주고, 학생이 [보내기]·[취소] 중 하나를 선택한다. AI의 판단 확신도가 낮으면 다듬은 질문 후보 2~3개 중에서 고르게 한다
- S-4
    기능: 전달 불가 안내
    설명: 질문이 거르기 대상으로 판정되면 "수업과 관련된 질문만 보낼 수 있습니다" 안내 문구를 표시한다
- S-5
    기능: 같은 질문 인원 표시
    설명: 자신의 질문과 같은 내용을 질문한 인원을 표시한다 (예: "12명이 같은 질문을 했습니다")
- S-6
    기능: 교수 질문 응답
    설명: 교수 질문이 전송되면 화면 상단에 문항과 남은 시간이 표시되고, 익명으로 1회 응답한다

5. 주요 흐름
----------------------------------------

[5.1 흐름 A: 학생 질문 (학생 → 교수)]

    ① 학생이 질문 입력            예: "방금 그거 왜 0임"
    ② 서버가 질문 시점 기준 최근 강의 음성 인식 결과를 조회
    ③ AI 호출 1회: 분류 + 강의 시점 매칭 + 질문 다듬기
    ④ 무관·부적절 → 질문 폐기, 학생에게 전달 불가 안내
       관련       → 학생에게 다듬은 질문 표시
    ⑤ 학생 승인 → 같은 강의 시점을 가리키는 질문 묶음에 합류 (없으면 새 묶음 생성)
    ⑥ 교수 화면의 질문 목록 갱신
    ⑦ 교수가 요청하면 가장 많은 질문을 음성으로 읽어 줌

[5.2 흐름 B: 교수 질문 (교수 → 학생)]

    ① 강의 음성 인식 결과에서 질문 형태의 문장(어미 기준)을 1차 감지
    ② 이후 5초간의 발화를 함께 수집
    ③ AI 호출 1회: 실제 질문인지 판별(수사적 질문 제외) + 문항 정리 + 답변 형식·선택지 생성
    ④ 교수 화면에 감지 알림 → 교수가 [보내기] 선택
    ⑤ 학생 화면에 문항 표시 (기본 45초), 학생 익명 응답 (1인 1회)
    ⑥ 마감 → 답변 분포는 서버가 직접 계산
    ⑦ AI 호출 1회: 흔한 오해, 다시 설명할 내용, 음성 요약문 생성
    ⑧ 교수 화면에 결과 표시, 교수가 요청하면 음성으로 읽어 줌

6. 구현 방법
----------------------------------------

[6.1 시스템 구조]

서버 1개 + 웹 화면 2개 + 데이터베이스

- 서버
    기술: Next.js API Route (Vercel 배포)
    역할: 질문 처리, AI 호출, 질문 묶기, 응답 집계. AI API 키는 서버에서만 사용
- 교수 화면
    기술: Next.js 페이지 /prof/[방코드]
    역할: 강의 음성 인식(Web Speech API), 질문 목록, 교수 질문 관리, 음성 출력(speechSynthesis)
- 학생 화면
    기술: Next.js 페이지 /s/[방코드]
    역할: 질문 입력·승인, 교수 질문 응답
- 데이터베이스
    기술: Supabase (PostgreSQL + Realtime)
    역할: 강의 인식 결과, 질문, 질문 묶음, 교수 질문, 응답 저장 및 실시간 갱신 (장애 시 2초 주기 조회로 대체)

[6.2 서버 처리 원칙]

- 모든 시각은 서버(데이터베이스) 기준으로 기록한다. 기기 간 시각 차이로 인한 매칭 오류를 방지하기 위함이다.
- 강의 음성 인식 결과는 문장 단위로 저장한다.
- 거르기는 AI 판정으로만 수행하며, 제외된 질문은 저장하지 않고 폐기한다.

[6.3 AI 호출 명세]

공통 사항

모델: 응답 속도 기준 가장 빠른 소형 모델 (예: gpt-4o-mini, Claude Haiku)
출력 형식: JSON으로 고정
제한 시간: 8초
호출 횟수: 학생 질문 1건당 1회 / 교수 질문 감지 1건당 1회 / 교수 질문 마감 1건당 1회

① 학생 질문 처리 (흐름 A)

- 입력
- 학생이 입력한 원문
- 질문 시점 기준 최근 3분간의 강의 음성 인식 결과 (문장 번호, 경과 시간 포함)
- 교안 PDF에서 추출한 핵심 용어 (업로드한 경우, 인식 오류 보정용)
- 출력
```json
{
"category": "관련",
"ref_line_ids": [43, 44],
"refined": "방금 행렬식을 0으로 놓으신 이유를 다시 설명해 주실 수 있나요?",
"confidence": 0.85,
"candidates": []
}
```

- category
    설명: 관련 / 무관 / 부적절
- ref_line_ids
    설명: 질문이 가리키는 강의 문장 번호. 질문 묶기에 사용하며 학생 화면에는 표시하지 않는다
- refined
    설명: 다듬은 질문
- confidence
    설명: 매칭·다듬기의 확신도 (0~1)
- candidates
    설명: 확신도가 낮을 때 제시할 다듬은 질문 후보 (최대 3개)

- 판정 기준: 수업·과제·시험·수업 운영에 관한 내용은 "관련"으로 본다. 판단이 애매한 경우 "관련"으로 처리하여 정상 질문이 누락되지 않도록 한다.

② 교수 질문 감지 (흐름 B)

- 입력: 질문 후보 문장, 이후 5초간의 발화, 최근 2분간의 강의 음성 인식 결과
- 출력: 실제 질문 여부, 정리된 문항, 답변 형식(선택형·단답형·서술형), 선택지(선택형의 마지막 선택지는 항상 "모르겠어요"), 예상 정답

③ 교수 질문 응답 분석 (흐름 B)

- 입력: 문항, 예상 정답, 관련 강의 내용, 서버가 계산한 답변 분포, 학생 응답 목록
- 출력: 흔한 오해(최대 2개), 다시 설명할 내용 1문장, 음성 요약문(15초 이내)

[6.4 예외 처리]

- AI 호출 실패·시간 초과 (학생 질문)
    처리: 원문을 그대로 전달하고 "AI 정리 없이 전달되었습니다"를 안내한다
- AI 호출 실패 (교수 질문 감지)
    처리: 해당 감지를 무시한다. 교수는 직접 입력으로 질문할 수 있다
- AI 호출 실패 (응답 분석)
    처리: 답변 분포만 표시한다
- 강의 음성 인식 결과가 없음 (수업 초반 등)
    처리: 강의 시점 없이 일반 질문으로 처리한다
- 음성 인식 중단
    처리: 자동으로 재시작한다
- 교수 질문 진행 중 새 질문 감지
    처리: 진행 중인 질문이 마감된 후 알림을 표시한다

7. 데이터 처리 원칙
----------------------------------------

- 강의 음성
    처리: 저장하지 않는다
- 강의 음성 인식 결과
    처리: 수업 중에만 저장하고, 수업 종료 시 삭제한다
- 거르기로 제외된 질문
    처리: 저장하지 않고 즉시 폐기한다
- 승인된 질문
    처리: 저장한다. 교수 화면에는 다듬은 질문만 표시하고 원문은 표시하지 않는다
- 학생 식별 정보
    처리: 수집하지 않는다. 기기별 익명 ID만 1인 1회 응답 확인 용도로 사용하며 화면에 표시하지 않는다

8. 결정 필요 사항
----------------------------------------

- D-1
    항목: 교안 PDF 업로드 필수 여부
    선택지: 필수 / 선택
    비고: 질문 시점 매칭은 강의 음성 인식으로 수행하므로 PDF는 필수가 아니다. PDF는 전문 용어 인식 오류 보정에 활용된다. 선택 사항으로 두는 것을 권장한다
- D-2
    항목: AI 모델
    선택지: gpt-4o-mini / Claude Haiku 등
    비고: 응답 속도 측정 후 결정
- D-3
    항목: 강의 내용 조회 범위
    선택지: 2분 / 3분 / 4분

    항목: 교수 질문 응답 시간
    선택지: 30초 / 45초 / 60초
    비고: 기본 45초

9. 기대 효과
----------------------------------------

- 학생
    효과: 심리적 부담 없이 질문할 수 있다. 질문을 정리하지 못해도 AI가 구체화한다. 같은 질문을 한 인원을 확인하여 "나만 모른다"는 불안이 줄어든다
- 교수
    효과: 학생들이 강의의 어느 부분에서 이해하지 못했는지 실시간으로 파악한다. 질문에 대한 응답률이 높아져 학생 이해도를 확인할 수 있다
- 수업
    효과: 수업 흐름을 끊지 않고 질문과 응답이 이루어진다. 학생이 개인 AI 챗봇으로 해결하던 질문이 교실 안의 소통으로 돌아온다
